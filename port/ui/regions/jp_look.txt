# The Japanese release's look: OrrePort's one table of regional differences (3.5 steps 2 and 3, 2026-11-19).
#
# Why a table: snatcherLeo decided (2026-11-17) that with the language set to Japanese and the player's Japanese disc added,
# the game takes the Japanese release's own look, all of its non-word differences together, with no switch of their own.
# "The swap list kept as data" (the plan's "Showing players what changes"): this one file is read by the swap code
# (port/src/pc_region_look.cpp, which hands the rows to pc_word_pictures.cpp and pc_lang_files.cpp), by the hub's
# "What changes" list (its words: the keys in ui/lang/en.txt), and later by OrrePort Studio's "region variants".
# Nothing here comes from a disc: names and descriptions only. The pictures and models themselves are read from the
# player's own Japanese disc while the game runs, never shipped.
#
# One row per asset, the columns separated by "|":
#   id         a stable name for the row (the UI Editor, mods and the log refer to it; never change one)
#   kind       picture or model
#   entry      the archive entry's name, the same on the US and Japanese discs (verified for every row, 2026-11-19)
#   archives   where the US game takes it from (archive names without ".fsys", comma-separated; main.dol = embedded in
#              the program); the Japanese copy is read from the same entry name on the Japanese disc
#   region     the release whose look it is (JP)
#   condition  when it applies: lang=ja (the game's language) and disc=GC6J01 (the player's Japanese disc is added).
#              The only condition the code knows today; a row with another one is skipped (logged)
#   what       the ui/lang key of the words saying what it shows in that release (the hub's "What changes" list).
#              *Changed 2026-11-21 (snatcherLeo: "we can just condense the Rui changes ... 'Rui wears her Japanese outfit' is
#              perfect for all of these"):* rows may share a key; the list shows each key's line once, so the five Rui
#              rows read "Rui wears her Japanese outfit." and the three Somek rows "Somek has his moustache."
#   how        how OrrePort swaps it:
#                sprite  the game draws it in pieces from its sprite table: the piece's record gets the Japanese
#                        picture's id and the picture is read from the disc when first drawn (the word pictures' path)
#                entry   the game looks the picture up by its id in code (no sprite record names it), or it is a 3D
#                        model: the archive is served with that one entry taken from the Japanese disc (the language
#                        files' path). The archive's own entry record then carries the Japanese entry's sizes, so the
#                        game sizes its buffers for it (models of another size included). Every model row is "entry"
#                none    not swapped yet (the note says why)
#   note       anything else (shown in the log; "colour depth only": the same artwork stored with more colours)
#
# The facts behind each row (verified 2026-11-19 by read-only studies of both discs; docs/engine/regions.md "The seven
# non-word Japanese pictures"): every entry keeps its name and resource id on both discs; the Japanese copies of one
# entry in several archives are identical. ORRE_NO_REGION_LOOK=1 turns every swap of this table off (a test switch).
