# Data the PC build places at its GameCube address (option 1, port-gaps 22; approved by snatcherLeo 2026-10-17).
# Read by tools/local/port/pcdata.py. Addresses and names only (from symbols.txt): no game data in this file.
#
# Why: the battle move scripts (the byte code fn_80211B94 runs) carry GameCube addresses inside their bytes: jumps to
# other script bytes, the variables they read and write, and constant tables. Rewriting every embedded address is not
# possible (they sit at odd offsets inside commands, and dtk does not see all of them), so the PC puts these bytes, and
# what they point at, at the same addresses as on the GameCube. MEM1 is mapped at 0x80000000 on the PC, and the heap
# arena starts after main.dol's data (0x80496740, B's arena change), so these addresses are free.
# The list is measured by tools/local/port/battlescript_addrs.py (walks every script from the 214-entry effect table
# and the named starts; 2026-10-17: 3,194 commands, embedded targets only in the ranges and variables below).
#
#   raw LO HI      main.dol's bytes [LO, HI) are copied to their address at startup, unchanged (big-endian, as on the
#                  disc). Symbols inside that pcdata would generate become absolute (the linker places them at their
#                  GameCube address), except two kinds that keep their own PC copy for the C code: symbols the PC code
#                  defines itself, and symbols the C declares with a typed (non-byte) declaration, which it reads
#                  natively (pointer tables like lbl_80375E24, message-id tables like lbl_80279E7C). The scripts see
#                  the big-endian copy at the GameCube address; these are constant tables, so both copies hold the
#                  same values (likely: no code writes them). Pointer slots in the copied bytes that point outside
#                  the fixed data get the target's PC address (big-endian) at startup.
#   var NAME T     a variable the scripts read or write that may also be shared with the C code: absolute at its
#                  GameCube address, its initial value converted to PC byte order as elements of type T (u8 / u16 /
#                  u32: how the script commands read it). .sbss variables start as zero.
