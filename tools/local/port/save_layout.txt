# Save block fields known from the game's code (hand-kept, each with its evidence; offsets and sizes only, no game
# data). savepc.py merges them into the traced fields of save_fields.txt, so a field stays swapped even when no
# save-trace run happened to read it. save_keep.txt still wins (text kept as bytes). Same syntax as save_keep.txt:
#   OFFSET SIZE                                   one field
#   records BASE STRIDE COUNT OFF:SIZE ...        the same fields in COUNT records of STRIDE bytes from BASE
#   mirror SRC SIZE DEST ...                      a struct copied whole: the fields found in [SRC, SRC + SIZE) (traced
#                                                 or listed here, after the keep list) repeated at each DEST

# Strategy Memo (section 12, block +0x82A8): a u16 count, then 500 records of 12 bytes from +0x82AC: the species id
# (u16, top bit = not yet viewed), the catching trainer's id (u32) and the Pokemon's personality value (u32).
# Evidence: memoInit (0x1F4 records, stride 12), memoDataSet, memoDataGetPokemonTrainerRndFromID / ...RndFromID
# (memo_candidate_8025FF18.c, memo_r57b_8025FD34_suffix.c). The traces had seen the trainer id only in records 0-1,
# so from record 2 on it reached the card in the PC's byte order (verified on P01's end save, 2026-10-27).
records 0x82AC 12 500 0:2 4:4 8:4

# Battle Mode's trainer records (section 14, block +0xE3E8, 2026-10-30, port-gaps 42). Each 0x1660-byte entry is
# built by menuCBBiosCreateTrainerHero (menu_middle.c): u16 trainer id +0, u16 kept id +2, u32 trainer kind +4
# (menuMiddleTrainerKind), then two whole HeroSaveData copies (0xB18 bytes, heroBiosCopy) at +0x2C and +0xB44;
# menuColosseumBattleSetup writes a u32 at +0x24 and copies each entry 0x5984 bytes further on. Entries: four from
# section +0x24 (savedataBattleGetEntryPtr, stride 0x1660), their four copies from +0x59A8, and the saved hero at
# +0xB328 (savedataBattleSetSavedHero, a 0x1660-byte memcpy). HeroSaveData is save section 2 (block +0x70, 0xB18), so
# its traced fields are mirrored into all 18 copies. No save trace had covered section 14 (3 fields), so the PC wrote
# it in its own byte order (verified on P24's end save: with these fields the player's entry, its copy and the saved
# hero match the console's byte for byte; the three computer trainers' entries then differ only in values).
records 0xE40C 0x1660 4 0:2 2:2 4:4 0x24:4
records 0x13D90 0x1660 4 0:2 2:2 4:4 0x24:4
records 0x19710 0x1660 1 0:2 2:2 4:4 0x24:4

# Battle Mode's run words and a suspended Mt. Battle run (section 14, block +0xE3E8, 2026-10-31, port-gaps 45).

# +0x1C. Suspending a run (menuSaveLoadSaveGame, gba_conv.c) copies the seven words to section +0xC98C and fills the
